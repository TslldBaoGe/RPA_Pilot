# 在线更新部署指南（国内 Linux 服务器 + Docker 容器直供）

## 现状

| 项 | 值 |
|---|---|
| 仓库 | https://github.com/TslldBaoGe/RPA_Pilot |
| 构建 | GitHub Actions：打 `v*` 标签即构建并发 Release（windows runner，约 2 分钟） |
| 最新 Release | `v0.1.8` —— `latest.yml` / `RPA_Pilot-0.1.8-setup.exe`(≈115.4 MB) / `.blockmap`(≈0.12 MB) |
| 更新源 | `http://8.134.166.149:8088/`（已写进 `electron-builder.yml`） |
| 服务器 | 国内腾讯云 Linux（`8.134.166.149`），8088 端口直供更新产物 |
| 客户端 | 启动后 25 秒、之后每 4 小时检查一次 → 后台下载 → 提示用户安装 |

> ⚠️ **换服务器后的迁移顺序**：更新源地址是**打包时烘进安装包**的。已装出去的客户端里仍是**旧服务器地址**，
> 必须等它们更新到「指向 `8.134.166.149`」的新版本之后，旧服务器才能退役。
> 也就是说：旧服务器先保持可用 → 发一个指向新地址的新版本 → 同事陆续更新过去 → 再下线旧机器。
> 本次换了地址，**必须重新打包**（见步骤 1）。

## 服务器上只有一条命令

每次在服务器上 `git pull` 之后，只需要跑这一条：

```bash
cd /path/to/RPA_Pilot
git pull
sudo bash scripts/server-update.sh
```

它依次做两件事，**都是幂等的**：

1. **`scripts/deploy-server.sh`** —— 应用仓库里的脚本/配置改动：重装 `sync-updates.sh`、重新生成便捷命令 `rpa-sync`、按需重建提供服务的容器（或 nginx）；
2. **`rpa-sync`** —— 拉取 GitHub 上最新的发行版写进更新目录；版本没变会自动跳过。

常用变体：

```bash
sudo bash scripts/server-update.sh --force          # 版本相同也重下（修复损坏的产物）
sudo bash scripts/server-update.sh --check          # 只看远端是什么版本，不下载
sudo SKIP_DEPLOY=1 bash scripts/server-update.sh    # 只同步，不重跑部署脚本（省几秒）
```

> 第一次在新机器上部署也直接用这一条即可（它会先完成部署、再同步）；想单独只做部署配置就按步骤 3 跑 `deploy-server.sh`。

## 0. 架构

```
你的电脑                 GitHub                          国内 Linux 服务器              同事的电脑
────────                ──────                          ────────────────              ──────────
git push  ──────────►   仓库 main
                         │
                         │ 打标签触发
                         ▼
                        GitHub Actions（windows runner）
                        构建安装包 → 挂成 Release 附件
                         │
                         ▼
                        Release v0.1.8  ──────►         你手动执行 sudo rpa-sync
                        ├ latest.yml                     拉取这 3 个文件 → 写进更新目录
                        ├ ....exe                        ──► 由独立 Docker 容器在 8088 端口
                        └ ....blockmap                        直接提供（只读挂载更新目录）  ──►  RPA_Pilot
                                                                                             自动检查 → 后台下载 → 提示安装
```

**角色分工：**

| 角色 | 职责 |
|---|---|
| GitHub 仓库 | 永远的项目源头，唯一的版本来源（git 标签） |
| GitHub Actions | 构建安装包并发布 Release（不需要你的电脑开着） |
| Linux 服务器 | 只负责「拉」和「托管」，**不需要装 Node / pnpm / 任何构建工具链** |
| 本地电脑 | 开发与测试 |
| 客户端 | 定期检查更新 → 后台下载 → 提示用户安装 |

**为什么让服务器「拉」而不是 GitHub「推」**：拉取只需要出站 HTTPS，Linux 服务器不用给公网开任何入站端口，防火墙那边什么都不用改。

## 1. 一次性准备

### 步骤 1：确认更新源地址

**当前使用（已写进 `electron-builder.yml`）：**

```
http://8.134.166.149:8088/
```

服务器在国内，客户端下载走国内链路，不再受跨境带宽拖累。

以后如果接了域名，把这行换掉并**重新打包**即可：

```yaml
publish:
  provider: generic
  url: http://8.134.166.149:8088/     # ← 必须以 / 结尾
```

**改完必须重新打包** —— 地址是打包时写进安装包内 `resources\app-update.yml` 的，改配置不影响已有的安装包。

改完先跑体检（会拦住占位地址、`127.0.0.1`、缺结尾斜杠、UNC 路径）：

```bash
pnpm release:check
```

> 这道检查是为了防止一个真实踩过的坑：本机联调用的 `http://127.0.0.1:8787/`
> 被当成正式版本发出去，所有同事的客户端都去连自己的本机，更新永远失败，
> 而且从安装包上完全看不出来。

### 步骤 2：推代码到 GitHub

```bash
git init && git add . && git commit -m "初次提交"
git remote add origin https://github.com/TslldBaoGe/RPA_Pilot.git
git branch -M main
git push -u origin main
```

### 步骤 3：在服务器上跑一键部署脚本

在服务器上 clone 仓库，然后：

```bash
cd /path/to/RPA_Pilot
git pull
sudo bash scripts/deploy-server.sh
```

脚本会把下面六件事一次做完，**并且可以反复执行（幂等）**：

| 步骤 | 做什么 |
|---|---|
| 1/6 | 准备更新目录。默认是 **`<仓库>/updates`**（已在 `.gitignore` 里）。目录已存在就不动它的属主和权限 |
| 2/6 | 把 `sync-updates.sh` 装到 `/usr/local/bin/`，并生成便捷命令 `rpa-sync`（仓库地址、更新目录、属主都固定进去） |
| 3/6 | 在指定端口提供 HTTP 服务。**默认起一个独立 Docker 容器**，不碰宿主机 nginx（很多人机器上 80 端口属于别的项目，动宿主机 nginx 容易把别人的站搞挂），失败才回退宿主机 nginx |
| 4/6 | 放行端口（自动识别 firewalld / ufw） |
| 5/6 | 自动拉取。**默认不装 cron** —— 由你手动执行 `rpa-sync`；要定时自动拉才设 `ENABLE_CRON=1` |
| 6/6 | 跑一次 `--check` 验证能连上 GitHub |

**默认的 Docker 方式**（`SERVE_MODE=auto` 且机器上有 docker 时走这条）：

- 容器名 `rpa-pilot-updates`，镜像 `nginx:alpine`（本地没有会尝试拉取，拉不动则用本地已有的 nginx 镜像）；
- `-p 8088:80`：宿主 8088 → 容器 80；
- `-v <更新目录>:/usr/share/nginx/html:ro`：把更新目录**只读**挂进容器当网站根；
- 容器里只有这三个更新产物，别的文件压根不存在，所以不需要额外写「只放行哪些路径」的规则；
- 容器参数有变化（端口或挂载目录不一致）时会自动删掉旧容器重建。

**回退到宿主机 nginx 方式**（`SERVE_MODE=nginx`，或没有可用 docker 时）：

写 `/etc/nginx/conf.d/rpa-pilot.conf`（**先备份，校验失败自动回滚**），内容——**注意它只放行更新产物，其余一律 404**：

```nginx
# 由 scripts/deploy-server.sh 生成，请勿手工修改（会被覆盖）
server {
    listen 8088;
    server_name _;

    root /path/to/RPA_Pilot/updates;    # 实际值 = TARGET_DIR
    autoindex off;

    # 只允许这三个东西：latest.yml、安装包、差量索引
    location ~ ^/(latest\.yml|RPA_Pilot-[^/]+\.exe|RPA_Pilot-[^/]+\.exe\.blockmap)$ {
        try_files $uri =404;
        add_header Cache-Control "no-store" always;
    }

    # 其余路径一律 404
    location / {
        return 404;
    }
}
```

> **为什么要限制路径**：如果直接 `root` 上去、什么路径都放行，而更新目录又恰好和
> 你的站点（或克隆下来的仓库）是同一个目录，那么 `.git/config`、源码、`package.json`
> 都会被公网访问到。只放行这三个模式既够 electron-updater 用，又不暴露别的任何东西。
>
> 脚本还会探测 nginx 是谁在管：systemd 管的就只新增这个 server 并 reload；
> 如果发现 nginx 是宝塔 / 1Panel / 手工启动的（不归 systemd 管），**它会跳过不动**，
> 只把这段配置打印出来让你手工加 —— 盲写 `/etc/nginx/conf.d` 对这类 nginx 不生效，还可能弄坏现有站点。

**可用环境变量覆盖默认值**（改完重跑脚本即可）：

```bash
sudo TARGET_DIR=/data/rpa-updates PORT=8088 bash scripts/deploy-server.sh

# 想让服务器每 15 分钟自动拉一次（默认不装 cron）
sudo ENABLE_CRON=1 bash scripts/deploy-server.sh
```

| 变量 | 默认值 | 说明 |
|---|---|---|
| `TARGET_DIR` | `<仓库>/updates` | 更新目录 |
| `PORT` | `8088` | 监听端口 |
| `SERVE_MODE` | `auto`（有 docker 就用容器） | `docker` / `nginx` / `none` / `auto` |
| `CONTAINER_NAME` / `IMAGE` | `rpa-pilot-updates` / `nginx:alpine` | Docker 方式的容器名与镜像 |
| `KEEP` | `3` | 保留最近几个安装包（**别设成 1**，回滚要用） |
| `WEB_USER` | 自动探测（nginx / www-data / apache / httpd） | 文件属主 |
| `WRAPPER_PATH` | `/usr/local/bin/rpa-sync` | 便捷命令的位置 |
| `LOG_FILE` | `/var/log/rpa-pilot-sync.log` | 同步日志 |
| `ENABLE_CRON` | `0` | 设为 `1` 才装 cron（默认手动执行） |
| `GH_PROXY` | `https://gh-proxy.com` | 安装包走加速镜像（`latest.yml` 仍直连 GitHub 并做 sha512 校验）；设空则全部直连 |
| `NGINX_START` | `0` | 仅 `SERVE_MODE=nginx` 时，设为 `1` 才会主动启动宿主机 nginx |
| `SKIP_FIREWALL` / `SKIP_CHECK` | `0` | 设为 `1` 跳过对应步骤 |

> ⚠️ **别忘了云厂商的安全组**：腾讯云控制台 → 安全组 → 放行 `8088` 入站。
> 系统防火墙开了但安全组没开，现象是「本机 curl 通、外面连不上」。

### 步骤 4：验证端到端

```bash
# 1) 同步一次（把安装包拉到本地，约 115 MB）
sudo rpa-sync
```

```bash
# 2) 验证对外可访问
curl -I http://8.134.166.149:8088/latest.yml      # 应 200
curl -I http://8.134.166.149:8088/package.json    # 应 404（源码不可访问）
curl -I http://8.134.166.149:8088/.git/config     # 应 404
```

```bash
# 3) 关键一步：服务器上的安装包与 latest.yml 里声明的 sha512 必须一致
#    （不一致说明下载坏了，那会让所有客户端更新失败）
cd /path/to/RPA_Pilot/updates       # 换成你的实际 TARGET_DIR
grep -m1 '^sha512:' latest.yml
sha512sum RPA_Pilot-*-setup.exe | awk '{print $1}' | xxd -r -p | base64 -w0; echo
```

两个 base64 值必须一模一样。

然后**在一台干净的机器上装最新安装包**，确认：

1. 「设置 → 软件更新」里显示的更新源是 `http://8.134.166.149:8088/`
2. 点「检查更新」提示已是最新版本（说明客户端能读到服务器上的 `latest.yml`）

只要这两条成立，整条链路就通了。之后发新版本，客户端会在 4 小时内自动发现。

## 2. 日常发版流程

```bash
# 平时开发照常推代码
git add . && git commit -m "..." && git push

# 要发版时打个标签（版本号写在标签里）
git tag v0.1.9
git push origin v0.1.9
```

之后：

| 谁 | 做什么 |
|---|---|
| GitHub Actions | 写入版本号 → 体检 → 类型检查 → 构建 → 校验产物更新源 → 发 Release |
| Linux 服务器 | 你跑 `sudo bash scripts/server-update.sh` → 应用脚本改动 + 下载 3 个文件写进更新目录 + 清理过老版本 |
| 同事的客户端 | 启动 25 秒后（或每 4 小时）检查 → 后台静默下载 → 提示「新版本已就绪」→ 用户点安装 → 静默升级并重启 |

**版本号的唯一来源是 git 标签。** CI 会把它写进 `package.json`，保证安装包版本、
`latest.yml` 版本、界面显示版本三者一致（不一致会导致更新判断出错）。

也可以在 GitHub Actions 页面手动触发（`workflow_dispatch`），填版本号即可。

## 3. 拉取脚本 `sync-updates.sh` / 便捷命令 `rpa-sync`

`rpa-sync` 是部署脚本生成的包装命令（把更新目录、属主、保留份数都固定好了），日常同步就用它；
`scripts/server-update.sh` 是「pull 完一条搞定」的入口，内部会先跑部署脚本、再调 `rpa-sync`。

**国内加速（重要）**：国内服务器直连 GitHub Releases 很慢 —— 实测约 **65 KB/s**，115 MB 要半小时以上。
所以安装包和差量索引默认走加速镜像 `gh-proxy.com`（实测 1.4 MB/s 以上，115 MB 十几秒）。
`latest.yml` 始终**直连 GitHub** 取，再拿它声明的 **sha512 校验安装包** ——
这样镜像即使被篡改、或传输损坏，都会在校验这一步被拦下；镜像不可用时自动回退直连。

想换镜像或全部直连：`GH_PROXY=<别的镜像>` 或 `GH_PROXY=` 重跑一次 `deploy-server.sh` 即可（会写进 `rpa-sync`）。

| 参数 | 说明 |
|---|---|
| `--target <目录>` | 更新目录 |
| `--keep <N>` | 保留最近几个安装包，默认 3 |
| `--owner <用户>` | 只把**脚本写入的那三个文件**的属主改成它（不递归改目录） |
| `--check` | 只看现在是什么版本，不下载 |
| `--force` | 版本相同也重下（修复损坏的产物） |
| `--base <URL>` | 换下载源（GitHub Enterprise 或自测用） |

脚本刻意**不依赖 jq、不依赖 flock**（很多服务器上没装），用 `mkdir` 做原子锁。
公开仓库不需要任何 Token。

它做的几个关键处理（每一条都是踩过的坑）：

1. 用 `releases/latest/download/<文件名>` 重定向直下，**不走 GitHub API**，所以不需要 jq 解析 JSON
2. 下载先落 `.new` 再 `mv` —— 同文件系统内 `mv` 是原子的，客户端不会拿到下到一半的文件
3. **`latest.yml` 最后落地** —— 它是客户端检查更新的入口，先放它会让客户端看到一个安装包还没就位的版本
4. **锁会自愈**：锁目录里记下持有者 PID。如果上次是被 kill 或断电中断的，下一次会发现持有者已不存在，自动清理陈旧锁继续干活 —— 否则**一次异常终止就会让更新永久静默停掉**
5. **所有 curl 都设了超时上限**（连接 20s、整包 30 分钟、并检测传输停滞），避免服务器接受连接后卡住导致同步永久挂起、锁被一直占着
6. `--owner` **只改自己写入的文件**，不递归改目录 —— 否则会把同目录下别的东西（比如克隆下来的仓库）的属主一起改掉

## 4. 关于 HTTPS

**内网/中间服务器不是必须用 HTTPS。** 当前就是 HTTP：

- GitHub → 服务器这一跳本身就是 HTTPS，安装包在公网传输是加密的
- 服务器 → 客户端这一跳，`latest.yml` 里有安装包的 **sha512**，下载损坏会被发现
- 不涉及域名、证书、客户端配置

> ⚠️ 但要注意：`8.134.166.149` 是**公网 IP**，所以「服务器 → 客户端」这一段走的是公网明文。
> 能劫持这条连接的人可以**同时替换 `latest.yml` 和安装包**，给所有客户端推任意代码 ——
> sha512 防不住这种情况（两个文件一起被换掉）。
> **建议后续加个域名并使用 Let's Encrypt**：服务器公网可达，`certbot --nginx`
> 一条命令就能拿到证书并自动续期，客户端零配置。

如果确实要自签 HTTPS，**先看清楚这条硬约束**：

> 公网 CA（Let's Encrypt 等）**不给 IP 地址和内网名字签证书**。所以用 IP 只能自签；
> 自签则**每台客户端的 Windows 都必须信任这张证书**，否则更新一定失败。

这不是理论，实测过 —— 连 `localhost` 的自签证书都会被拒：

```
更新出错：net::ERR_CERT_AUTHORITY_INVALID
```

自签证书生成（注意 **SAN 必填**，现代客户端完全忽略 CN）：

```bash
sudo mkdir -p /etc/nginx/ssl && cd /etc/nginx/ssl
sudo openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout rpa-pilot.key -out rpa-pilot.crt \
  -subj "/C=CN/O=YourCompany/CN=8.134.166.149" \
  -addext "subjectAltName=IP:8.134.166.149"
```

客户端装证书：

```powershell
certutil -addstore Root rpa-pilot.crt        # 需要管理员
```

> 实测小坑：用 PowerShell 的 `Import-Certificate` 导入根证书会报
> `UI is not allowed in this operation`（导入根证书要弹安全确认框）。
> 用 `certutil` 或组策略没这个问题。

## 5. 回滚

**electron-updater 不会降级**，所以回滚不是「把 `latest.yml` 换回旧版本」，而是：

```bash
git checkout v0.1.8                    # 回到出问题之前
git checkout -b hotfix/rollback
# 把 package.json 版本号改高，例如 0.1.10
git commit -am "回滚到 0.1.8 的行为，以 0.1.10 发布"
git tag v0.1.10 && git push origin v0.1.10
```

`--keep` 默认保留最近 3 个安装包，所以旧包还在。

## 6. 排错清单

| 现象 | 原因与处理 |
|---|---|
| 客户端「检查更新」失败 | 先验证：`curl -v http://8.134.166.149:8088/latest.yml`。404 说明还没同步或有路径问题；连不上说明端口/安全组没放行 |
| 本机 curl 通、外面连不上 | 云厂商安全组没放行。腾讯云控制台 → 安全组 |
| 容器没起来 / 起来了但访问不到 | `docker ps -a --filter name=rpa-pilot-updates` 看状态，`docker logs rpa-pilot-updates` 看日志；确认 8088 没被别的进程占用 |
| 容器在跑但仍 404 | 确认更新目录里真的有文件（`ls -l <TARGET_DIR>`）；容器是**只读**挂载该目录，文件不在里面就没有 |
| 改了端口/目录没生效 | 重跑一次 `deploy-server.sh`，它会检测到容器参数变化并自动重建 |
| 重跑脚本后行为仍不对（比如请求被跳走、或返回的不是本机文件） | 容器参数一致时脚本不会重建它。若这个容器是被更早的方案创建的、带有多余挂载，先 `sudo docker rm -f rpa-pilot-updates` 再重跑脚本 |
| 客户端报 `ERR_CERT_AUTHORITY_INVALID` | 用了 HTTPS 但证书不被信任。见第 4 节 |
| 检查成功但总说已是最新 | 服务器上 `latest.yml` 还是旧版本 → 手动跑一次 `sudo rpa-sync`；默认没装 cron，不会自己拉 |
| 同步脚本报「上一次同步还在进行」 | 如果确实是并发（上一次还在下载），等它跑完即可；如果持有者已死，**脚本会自动清理陈旧锁**，日志里会写「发现陈旧锁…自动清理后继续」 |
| 下载安装包失败 | 服务器上文件不完整。跑 `sudo rpa-sync --force` 强制重下 |
| 服务器拉取安装包很慢 | 默认已走加速镜像。若这个镜像也慢，换一个 `GH_PROXY` 重跑 `deploy-server.sh`；要直连就设 `GH_PROXY=`（更慢但最稳） |
| 报「安装包 sha512 与 latest.yml 不一致」 | 下载损坏或镜像不可信。脚本会先自动回退直连重试；仍失败就 `sudo rpa-sync --force` |
| 同事装了但从不提示更新 | 他装的是**旧安装包**（更新源指向别的地址），换成最新安装包重装 |
| Nginx 方式起不来 / 读不到文件 | 先看脚本是否提示「nginx 不归 systemd 管」；CentOS/RHEL 上 SELinux 可能拦，或确认目录对 Web 账号可读 |
| Nginx 配置被我改坏了 | 脚本每次都会备份到 `/etc/nginx/conf.d/rpa-pilot.conf.bak.<时间戳>`，拷回来即可；或直接删掉该文件重跑脚本 |
| 客户端更新日志在哪 | `%APPDATA%\rpa-pilot\update.log`；启动诊断 `boot.log` 同目录 |

## 7. 附：手工部署（不想跑脚本时）

用**专用目录**放更新产物，别和别的站点/仓库混在一起：

```bash
# 1) 更新目录
sudo mkdir -p /var/www/rpa-pilot/updates
sudo chmod 755 /var/www/rpa-pilot/updates

# 2) Nginx（只放行更新产物）
sudo tee /etc/nginx/conf.d/rpa-pilot.conf >/dev/null <<'EOF'
server {
    listen 8088;
    server_name _;
    root /var/www/rpa-pilot/updates;
    autoindex off;
    location ~ ^/(latest\.yml|RPA_Pilot-[^/]+\.exe|RPA_Pilot-[^/]+\.exe\.blockmap)$ {
        try_files $uri =404;
        add_header Cache-Control "no-store" always;
    }
    location / { return 404; }
}
EOF
sudo nginx -t && sudo systemctl reload nginx

# 3) 防火墙
sudo firewall-cmd --permanent --add-port=8088/tcp && sudo firewall-cmd --reload
# Ubuntu：sudo ufw allow 8088/tcp

# 4) 拉取脚本 + cron（要自动拉才需要）
sudo curl -fsSL -o /usr/local/bin/sync-updates.sh \
  https://raw.githubusercontent.com/TslldBaoGe/RPA_Pilot/main/scripts/sync-updates.sh
sudo chmod +x /usr/local/bin/sync-updates.sh
( sudo crontab -l 2>/dev/null; \
  echo '*/15 * * * * REPO=TslldBaoGe/RPA_Pilot TARGET_DIR=/var/www/rpa-pilot/updates OWNER=nginx LOG_FILE=/var/log/rpa-pilot-sync.log /usr/local/bin/sync-updates.sh' \
) | sudo crontab -
```

### Windows 服务器

用 `scripts/sync-updates.ps1`（功能等价），配「任务计划程序」每 15 分钟跑一次，Web 服务器用 IIS。

⚠️ IIS 上**必须**给 `.yml` 和 `.blockmap` 配 MIME 映射，否则一律 404。在该目录放一个 `web.config`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
  <system.webServer>
    <staticContent>
      <mimeMap fileExtension=".yml" mimeType="text/yaml" />
      <mimeMap fileExtension=".blockmap" mimeType="application/octet-stream" />
    </staticContent>
    <directoryBrowse enabled="false" />
  </system.webServer>
</configuration>
```

> Nginx 没有这个问题：它对未知扩展名一律按 `application/octet-stream` 正常返回，
> 而 electron-updater 只读内容、不看 Content-Type。

## 8. 安全边界

1. **客户端不在内网时更新会失败，但软件照常用。** 服务器连不上时只在 `update.log` 记一条、界面显示原因，应用功能不受影响，4 小时后自动重试。
2. **更新目录的写权限要收紧。** 不签名的话，**谁能写那个目录谁就能给所有客户端推任意代码**。目录应只有 root 可写，Web 账号只读。
3. **公网 HTTP 的风险**见第 4 节 —— 建议后续上 Let's Encrypt。
4. **公有仓库意味着源码是公开的。** 如果业务逻辑不宜公开，改成私有仓库：Actions 仍可用，但私有仓库的 Windows runner 按 2 倍分钟数计费；拉取脚本要改用带 Token 的 API 方式。
