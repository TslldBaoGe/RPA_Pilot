# 在线更新部署指南（Linux 中间服务器 + Nginx）

## 0. 架构

```
你的电脑                 GitHub                        Linux 中间服务器            同事的电脑
────────                ──────                        ────────────────           ──────────
git push  ──────────►   仓库 main
                         │
                         │ 打标签触发
                         ▼
                        GitHub Actions（windows runner）
                        构建安装包 → 挂成 Release 附件
                         │
                         ▼
                        Release v0.1.4  ──────►      cron 每 15 分钟
                        ├ latest.yml                 跑 sync-updates.sh
                        ├ ....exe                    下载产物 → 写进 Nginx 目录
                        └ ....blockmap                                       ──►  RPA_Pilot.exe
                                                                                 自动检查更新
```

**角色分工：**

| 角色 | 职责 |
|---|---|
| GitHub 仓库 | 永远的项目源头，唯一的版本来源（git 标签） |
| GitHub Actions | 构建安装包并发布 Release（不需要你的电脑开着） |
| Linux 中间服务器 | 只负责「拉」和「托管」，**不需要装 Node / pnpm / 任何构建工具链** |
| 本地电脑 | 开发与测试 |
| 客户端 | 定期检查更新，发现新版本 → 后台下载 → 提示用户安装 |

**为什么让服务器「拉」而不是 GitHub「推」**：拉取只需要出站 HTTPS，Linux 服务器不用给公网开任何入站端口，防火墙那边什么都不用改。

## 1. 一次性准备

### 步骤 1：确定更新源地址，改配置并重新打包

先定下客户端要访问的地址（当前实际使用）：

```
http://43.173.66.157:8088/
```

> 说明：服务器上的更新目录是 `/swagtslld/RPA_Pilot`，
> Nginx 的 `root` 直接指向它，所以 `latest.yml` 就在这个端口的**根路径**下。
> 那台机器的 80 端口已被另一个项目占用，因此本项目单独用 8088。
> 以后如果接了域名，换成 `http://updates.你的域名/` 并重新打包即可。

改 `electron-builder.yml`：

```yaml
publish:
  provider: generic
  url: http://43.173.66.157:8088/     # ← 改这里，必须以 / 结尾
```

**必须重新打包才生效** —— 这个地址是打包时写进安装包内 `resources\app-update.yml` 的。

改完先跑体检（它会拦住占位地址、`127.0.0.1`、缺结尾斜杠、UNC 路径）：

```bash
pnpm release:check
```

> 这道检查是为了防止一个真实踩过的坑：本机联调用的 `http://127.0.0.1:8787/`
> 被当成正式版本发出去，所有同事的客户端都去连自己的本机，更新永远失败，
> 而且从安装包上完全看不出来。

### 步骤 2：推代码到 GitHub

```bash
cd /path/to/RPA_Pilot
git init && git add . && git commit -m "初次提交"
git remote add origin https://github.com/TslldBaoGe/RPA_Pilot.git
git branch -M main
git push -u origin main
```

### 步骤 3：在 Linux 服务器上准备更新目录

```bash
sudo mkdir -p /swagtslld/RPA_Pilot
# 属主改成 Nginx 的运行账号：CentOS/RHEL 通常是 nginx，Debian/Ubuntu 是 www-data
sudo chown -R nginx:nginx /swagtslld/RPA_Pilot
# 目录权限收紧：只有属主可写，符合「更新目录的写权限要收紧」这条安全要求
sudo chmod 755 /swagtslld/RPA_Pilot
```

Nginx 配置 `/etc/nginx/conf.d/rpa-pilot.conf`：

```nginx
server {
    listen 8088;
    server_name 43.173.66.157;    # 有域名后换成域名

    root /swagtslld/RPA_Pilot;
    autoindex off;

    location / {
        try_files $uri =404;
        # latest.yml 是更新入口，绝不能被缓存住，否则客户端看不到新版本
        add_header Cache-Control "no-store" always;
    }
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx

# 放行 8088（这台机器 80 已被别的项目占用，更新走独立端口互不干扰）
# firewalld（CentOS/RHEL/腾讯云常见）：
sudo firewall-cmd --permanent --add-port=8088/tcp && sudo firewall-cmd --reload
# ufw（Debian/Ubuntu）：
# sudo ufw allow 8088/tcp
```

> **别忘了两处防火墙**：系统防火墙（上面这条）**和云厂商的安全组**。
> 腾讯云还需要在控制台的「安全组」里放行 8088 入站，否则本机 curl 通、外面连不上。

验证（在服务器本机跑）：

```bash
curl -I http://43.173.66.157:8088/latest.yml
```

现在应该返回 404（目录还空着）—— 这恰恰说明 Nginx 通了。等同步脚本跑过一次就会变成 200。

> **好消息**：IIS 那个「`.yml` / `.blockmap` 不配 MIME 映射就 404」的坑，**Nginx 上没有**。
> Nginx 对未知扩展名一律按 `application/octet-stream` 正常返回，
> 而 electron-updater 只读内容、不看 Content-Type。想严谨可以加 `types { text/yaml yml; }`。

### 步骤 4：部署拉取脚本 + cron

```bash
sudo install -m 0755 scripts/sync-updates.sh /usr/local/bin/sync-updates.sh

# 先手动跑一次确认能通（只查版本，不下载）
sudo /usr/local/bin/sync-updates.sh --target /swagtslld/RPA_Pilot --check

# 真同步一次
sudo /usr/local/bin/sync-updates.sh --target /swagtslld/RPA_Pilot --owner www-data
```

确认无误后加 cron（每 15 分钟）：

```bash
sudo crontab -e
# 加入这一行：
*/15 * * * * REPO=TslldBaoGe/RPA_Pilot TARGET_DIR=/swagtslld/RPA_Pilot OWNER=www-data LOG_FILE=/var/log/rpa-pilot-sync.log /usr/local/bin/sync-updates.sh
```

脚本的常用参数：

| 参数 | 说明 |
|---|---|
| `--target <目录>` | 更新目录，默认 `/swagtslld/RPA_Pilot` |
| `--keep <N>` | 保留最近几个安装包，默认 3（**别设成 1**，回滚要用） |
| `--owner <用户>` | 同步后改属主，例如 `www-data` |
| `--check` | 只看现在是什么版本，不下载 |
| `--force` | 版本相同也重下（修复损坏的产物） |
| `--base <URL>` | 换下载源（GitHub Enterprise 或自测用） |

脚本刻意**不依赖 jq、不依赖 flock**（很多服务器上没装），用 `mkdir` 做原子锁。公开仓库不需要任何 Token。

它做的几个关键处理（都是踩过的坑）：

1. 用 `releases/latest/download/<文件名>` 重定向直下，**不走 GitHub API**，所以不需要 jq 解析 JSON
2. 下载先落 `.new` 再 `mv` —— 同文件系统内 `mv` 是原子的，客户端不会拿到下到一半的文件
3. **`latest.yml` 最后落地** —— 它是客户端检查更新的入口，先放它会让客户端看到一个安装包还没就位的版本

### 步骤 5：发第一个版本

```bash
git tag v0.1.4
git push origin v0.1.4
```

Actions 会自动构建、校验产物里的更新源、发布 Release；15 分钟内服务器就会把它拉下来。

然后用构建出的安装包发给同事。**此前构建的所有安装包（更新源指向 `127.0.0.1` 或占位地址）都不能发。**

> ⚠️ 如果 `publish.url` 还是占位地址，**打标签后构建会在「发版配置体检」那步失败** —— 这是故意的。

## 2. 日常发版流程

```bash
# 平时开发照常推代码
git add . && git commit -m "..." && git push

# 要发版时打个标签
git tag v0.1.5
git push origin v0.1.5
```

之后全自动：

| 谁 | 做什么 |
|---|---|
| GitHub Actions | 写入版本号 → 体检 → 类型检查 → 构建 → 校验产物更新源 → 发 Release |
| Linux 服务器 | cron 发现新版本 → 下载 3 个文件 → 写进 Nginx 目录 → 清理过老版本 |
| 同事的客户端 | 启动 25 秒后（或每 4 小时）检查 → 后台静默下载 → 提示「新版本已就绪」→ 用户点安装 → 静默升级并重启 |

**版本号的唯一来源是 git 标签。** CI 会把它写进 `package.json`，保证安装包版本、`latest.yml` 版本、界面显示版本三者一致（不一致会导致更新判断出错）。

也可以在 GitHub Actions 页面手动触发（`workflow_dispatch`），填版本号即可。

## 3. 关于 HTTPS

**内网中间服务器不是必须用 HTTPS。** 推荐的起步做法就是上面配的 HTTP：

- GitHub → 服务器这一跳本身就是 HTTPS，安装包在公网传输是加密的
- 服务器 → 客户端在内网，且 `latest.yml` 里有安装包的 **sha512**，下载损坏会被发现
- 不涉及域名、证书、客户端配置，最省事

如果确实要 HTTPS，**先看清楚这条硬约束**：

> 公网 CA（Let's Encrypt 等）**不给 IP 地址和内网名字签证书**。
> 所以用 IP 或 `xxx.corp.local` 这类名字，只能自签；
> 自签则**每台客户端的 Windows 都必须信任这张证书**，否则更新一定失败。

这不是理论，实测过 —— 连 `localhost` 的自签证书都会被拒：

```
更新出错：net::ERR_CERT_AUTHORITY_INVALID
```

**三条路：**

| 做法 | 客户端要不要动 | 前提 |
|---|---|---|
| **保持 HTTP** | 不用动 | 内网可信（推荐起步用这个） |
| Let's Encrypt + **DNS-01 验证** | **不用动** | 有你能改 DNS 的域名。DNS-01 靠加 TXT 记录验证，**服务器不需要暴露到公网** |
| 自签 / 内网 CA | **每台都要装证书** | 没有可控域名。域环境可用组策略下发 |

自签证书生成（注意 **SAN 必填**，现代客户端完全忽略 CN）：

```bash
sudo mkdir -p /etc/nginx/ssl && cd /etc/nginx/ssl
sudo openssl req -x509 -newkey rsa:2048 -nodes -days 3650 \
  -keyout rpa-pilot.key -out rpa-pilot.crt \
  -subj "/C=CN/O=YourCompany/CN=10.0.0.5" \
  -addext "subjectAltName=IP:10.0.0.5"
```

Nginx 换成：

```nginx
listen 443 ssl;
ssl_certificate     /etc/nginx/ssl/rpa-pilot.crt;
ssl_certificate_key /etc/nginx/ssl/rpa-pilot.key;
ssl_protocols       TLSv1.2 TLSv1.3;
```

客户端装证书：

```powershell
certutil -addstore Root rpa-pilot.crt        # 需要管理员
```

> 实测小坑：用 PowerShell 的 `Import-Certificate` 导入根证书会报
> `UI is not allowed in this operation`（导入根证书要弹安全确认框）。
> 用 `certutil` 或组策略没这个问题。

## 4. 回滚

**electron-updater 不会降级**，所以回滚不是「把 `latest.yml` 换回旧版本」，而是：

```bash
git checkout v0.1.4                    # 回到出问题之前
git checkout -b hotfix/rollback
# 把 package.json 版本号改高，例如 0.1.6
git commit -am "回滚到 0.1.4 的行为，以 0.1.6 发布"
git tag v0.1.6 && git push origin v0.1.6
```

`sync-updates.sh --keep` 默认保留最近 3 个安装包，所以旧包还在。

## 5. 排错清单

| 现象 | 原因与处理 |
|---|---|
| 客户端「检查更新」失败 | 先验证地址：`curl -v http://43.173.66.157:8088/latest.yml`。404 说明目录或 Nginx 配置不对；连不上说明端口没放行 |
| 客户端报 `ERR_CERT_AUTHORITY_INVALID` | 用了 HTTPS 但证书不被信任。见第 3 节 |
| 检查成功但总说已是最新 | 服务器上 `latest.yml` 还是旧版本 → 看 `/var/log/rpa-pilot-sync.log`，多半是 cron 没跑或 GitHub 上还没发 Release |
| 同步脚本报「上一次同步还在进行」 | 上次异常退出留下了 `/swagtslld/RPA_Pilot/.sync-lock` 目录。确认没有进程在跑后 `rmdir` 它 |
| 下载安装包失败 | 服务器上文件不完整。跑 `sync-updates.sh --force` 强制重下 |
| 同事装了但从不提示更新 | 他装的是**旧安装包**（更新源指向 `127.0.0.1`），换成最新安装包重装 |
| 客户端更新日志在哪 | `%APPDATA%\rpa-pilot\update.log`；启动诊断 `boot.log` 同目录 |
| CentOS/RHEL 上 Nginx 读不到证书 | SELinux 拦的：`semanage fcontext -a -t httpd_sys_content_t "/etc/nginx/ssl(/.*)?" && restorecon -Rv /etc/nginx/ssl` |

## 6. 附：Windows 服务器

如果中间服务器是 Windows，用 `scripts/sync-updates.ps1`（功能等价），配「任务计划程序」每 15 分钟跑一次，Web 服务器用 IIS。

⚠️ IIS 上**必须**给 `.yml` 和 `.blockmap` 配 MIME 映射，否则一律 404。在该目录放一个 `web.config`：

```xml
<?xml version="1.0" encoding="UTF-8"?>
<configuration>
  <system.webServer>
    <staticContent>
      <mimeMap fileExtension=".yml" mimeType="text/yaml" />
      <mimeMap fileExtension=".blockmap" mimeType="application/octet-stream" />
    </staticContent>
    <directoryBrowse enabled="false" />
  </system.webServer>
</configuration>
```

## 7. 安全边界

1. **客户端不在内网时更新会失败，但软件照常用。** 服务器连不上时只在 `update.log` 记一条、界面显示原因，应用功能不受影响，4 小时后自动重试。
2. **公有仓库意味着源码是公开的。** 如果业务逻辑不宜公开，改成私有仓库：Actions 仍可用，但私有仓库的 Windows runner 按 2 倍分钟数计费；拉取脚本需要改用带 Token 的 API 方式。
3. **更新目录的写权限要收紧。** 不签名的话，**谁能写那个目录谁就能给所有客户端推任意代码**。`latest.yml` 里的 sha512 只保证传输没坏，不保证来源可信。
